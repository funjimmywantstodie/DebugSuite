# Choosing a data display

[UI docs](README.md) · [Runnable examples](examples/README.md)

## Data and output

| Display | Use when | Feed it with |
| --- | --- | --- |
| [List](data.md#list) | Flat records need columns, filtering, sorting, or selection: functions, events, key/value rows. | `SetRecords` replaces rows; `Append` adds/replaces rows by ID. |
| [Tree](data.md#tree) | Data has nested structure: tables, arguments, instance hierarchies. Expand only the branches you need. | `SetNodes`; `children` for known branches, `loadChildren` for lazy branches. |
| [Plain text viewer](data.md#text-and-syntax-highlighting) | Read a long string, selected value, formatted dump, or explanation with scrolling. | `NewTextViewer({ text = value })`, then `SetText`. |
| [Highlighted text viewer](data.md#text-and-syntax-highlighting) | Read Lua/Luau source or a dump formatted as Lua. | Add `syntax = "luau"` or `"lua"`; `GetText` stays raw. |
| [Editable text viewer](data.md#text-and-syntax-highlighting) | Edit multiline text or code. | Add `editable = true`; use `OnChanged`/`GetText`. Highlighting is optional. |
| [Console](logging.md#console) | Keep a chronological stream of messages with levels: traces, progress, warnings. | `NewEntry(text, level)` or `Append(entries)`; set `maxEntries`. |
| [Built-in console](logging.md#console) | Share one log across the app without placing a console in every tab. | `window:Log`; `OpenConsole` shows it. `captureLogs` optionally captures LogService. |
| [Notification](logging.md#notification) | Briefly call attention to completion, failure, or another important event. | `window:Notify`; the full text also goes to the built-in console. |
| [Label](controls.md#labels) | Show a small read-only status, count, or caption without an input field. | `NewLabel({ text = value })`, then `SetText`; `GetText` returns the raw string. |

Lists and trees render rows near the viewport. A text viewer shows one text block;
a console keeps separate entries and drops the oldest at its limit. Notifications
show at most three toasts and only the first line of each message.

For a simple results list, use `NewList({ showHeader = false, columns = ... })`
to hide the sorting headers and let rows use that space. See the
[headerless list example](data.md#list). Keep `columns` to define the displayed values.

## Values and actions

| Control | Use when | Read/update |
| --- | --- | --- |
| [Textbox](controls.md) | Enter or display one short string: search, a name, a single value. | `SetValue`/`GetValue`; constructor callback on focus loss, `OnChanged` for live updates, `OnSubmitted` for Enter only. `SetEnabled(false)` makes it read-only. |
| [Toggle](controls.md) | Represent an editable boolean: enabled, paused, an on/off setting. | `SetValue`/`GetValue`; `OnChanged` receives a boolean. |
| [Dropdown](controls.md) | Choose one string from a known set: log level, mode, category. | `options`, `SetOptions`, `SetValue`/`GetValue`; `OnChanged` receives a string or `nil`. |
| [Button](controls.md) | Trigger an action, such as opening details or refreshing data. Its caption can show a short count/status. | Click callback; `SetText` updates the caption. |
| [Menu](controls.md) | Group actions for the current data: refresh, clear, inspect. | `items` contains captions and callbacks. Use a dropdown for a selected value. |

Control `text` is a caption or textbox placeholder. Text viewer `text` is content;
list/tree/console `text` names the instance. Set actual control values with
`SetValue`, or toggle/dropdown `value` at construction.

## Combining displays

| Task | Pattern | Example |
| --- | --- | --- |
| Inspect an ordinary table | List for flat key/value pairs; tree for nested tables; viewer for the selected value. | [Table inspector](examples/table-inspector.lua) uses tree + viewer and handles cycles. |
| Browse many records | List + search textbox + viewer/tree for selected details. | [Workbench](examples/workbench.lua) demonstrates filtering, sorting, and selection. |
| Inspect a function | List of functions → select one → tree for arguments/metadata and viewer for available source text. | Wire `OnSelected` to populate details; fetching function data is your app's job. |
| Edit settings | Textboxes, toggles, and dropdowns in a section or panel. | [Basic tabs](examples/basic-tabs.lua), [workbench](examples/workbench.lua). |
| Monitor activity | Console for history + notification for important events. | [Workbench](examples/workbench.lua). |
| Open a dedicated tool | Button → owned floating window with the displays it needs. | [Table inspector](examples/table-inspector.lua); closing hides it for reuse. |

[Rows, panels, and split panes](layouts.md) arrange displays. A split pane is
useful for a browser beside its details; a scrolling panel holds multiple controls.
[Tabs and windows](windows.md) group tools: tabs share the main UI, floating
windows let you keep a specific inspector open beside it.

Keep original values in list `record.data` or tree `node.data`; format only the
visible cells/captions. Text viewers and consoles accept strings, not tables.
`tostring(table)` identifies the table rather than dumping its contents—build
records/nodes or format a dump yourself. The UI does not fetch executor data,
serialize tables, evaluate editor text, or validate code. Handle those operations
in your callbacks. Charts and images currently require your own Roblox instances;
there are no dedicated SimpleUI chart/image constructors.
